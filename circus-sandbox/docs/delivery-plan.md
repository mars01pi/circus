## 完成定义与范围

完整交付必须覆盖七个领域：统一 API、生命周期、基础设施、隔离运行时、environment、workspace、pool。Docker、Kubernetes、containerd 和 runc、gVisor、Kata、Firecracker 全部属于完成定义，不是可选候选或另行产品选择。现状“未实现”只描述缺口，不能把需求改成非目标。

本计划不修改 `circus-paseo/`，不把 Paseo CI 当作沙箱验证；不复制 OpenSandbox 的接口或测试通过状态；配置持久化尚未选定，不预选数据库或 ORM。以上边界不删除任何沙箱后端、运行时、快照或池需求。

### 支持与证据规则

先保留已实现 Docker + runc 的准确边界，再按下面依赖有序的 PR 扩展。只有对应实现合并且真实环境证据齐全，才能把某项写成已支持。没有真实适配器时必须明确拒绝请求，禁止空实现、字符串别名、静默改用 runc 或更弱隔离。

基础设施负责部署/调度，运行时负责隔离，不能把 Kubernetes 等同于 containerd，也不能把 RuntimeClass 名称、Docker runtime 参数或已安装二进制当作运行时集成。最低交付路径为 Docker + runc、Kubernetes + runc、独立 containerd + runc、containerd + gVisor、containerd + Kata，以及真正启动 Firecracker microVM 的适配路径。具体 shim/provider/版本由对应 PR 固定并验证；不要求所有基础设施与运行时的笛卡尔积，但这六条路径必须全部交付，且每个命名运行时都有真实隔离证据。

每条最低路径都要完成 create/start/run/pause/resume/destroy、命令与文件操作、显式资源和权限、所有权及失败回收。后端不能原生提供的转换必须由真实 provider/runtime 集成实现，不能以“不支持 pause”关闭整条路径；其他未承诺组合可以明确拒绝。快照模式另列能力矩阵，文件快照不暗示进程/内存检查点。

#### 3.5 三种快照语义、预启动与池

已有内存代码快照不需要重建。它按字节/条目预算捕获普通文件/目录、拒绝符号链接和特殊节点，恢复成独立 workspace；进程退出后内存值不持久存在。新增的 `save_file`/`load_file` 只把同一内容发布为调用方指定宿主路径上的有界、版本化、自定界文件归档：加载按实际剩余字节、调用方单文件上限和预算校验后分配，拒绝重复/不可移植路径、未知类型、截断与尾随字节。归档不是执行会话继续、容器镜像、客户机内存或进程检查点，也不含配额、加密、保留或租户隔离；调用方拥有路径、存储和租户范围，agent 原生会话文件必须位于被捕获的 workspace 内。Paseo 接入仍未实现。

当前 Docker 使用只读根与有界 tmpfs 工作区，`docker commit` 不包含 tmpfs 写入；不能沿用“提交容器可写层即可恢复代码”的承诺。运行时文件快照必须对声明范围做受限归档/恢复，或选择经证明包含该范围的真实机制，恢复失败必须失败关闭。进程/VM 内存检查点只能由另有实现和证据的能力声明，不由本计划文件快照暗示支持。
